# Charless言語 拡張提案書 (Draft)

Charless言語のシンプルさ（数字のみ）を維持しつつ、実用的なアプリケーション開発に耐えうる機能拡張を提案します。本提案はv3仕様の予約領域を活用します。

## 1. モジュールシステム (インポート機能)

大規模開発に向けたファイル分割機能を導入します。

- **使用領域**: `000-009` (システム系)
- **提案命令**:
    - `005`: **IMPORT**
        - スタック上の文字列（ファイルパス）を読み取り、そのファイルを現在のプログラムにリンク・展開する。
        - 既に読み込まれているファイルは無視する（Once保証）。

**コード例**:
```cless
# "lib.cless" をスタックにプッシュ (文字列の数値化は省略)
... 
005200 # IMPORT実行
```

## 2. 動的配列 (Vector)

固定メモリ (`0-999...`) の直接操作だけでなく、可変長の動的配列を言語レベルでサポートします。

- **使用領域**: `550-559` (動的メモリ管理)
- **提案命令**:
    - `550`: **V_NEW** (サイズ -> リファレンスID)
        - スタックから初期サイズをポップし、配列を作成。リファレンスIDをプッシュ。
    - `551`: **V_PUSH** (リファレンスID, 値 -> void)
        - 配列の末尾に値を追加。
    - `552`: **V_GET** (リファレンスID, インデックス -> 値)
        - 値を取得。
    - `553`: **V_SET** (リファレンスID, インデックス, 値 -> void)
        - 値を上書き。
    - `554`: **V_LEN** (リファレンスID -> 長さ)
        - 配列の長さを取得。

## 3. 連想配列 (Hash Map)

キーと値のペアを保持するデータ構造を導入します。

- **使用領域**: `560-569` (予約領域を利用)
- **提案命令**:
    - `560`: **M_NEW** (void -> リファレンスID)
    - `561`: **M_PUT** (リファレンスID, Key文字列, Value -> void)
    - `562`: **M_GET** (リファレンスID, Key文字列 -> Value)
    - `563`: **M_DEL** (リファレンスID, Key文字列 -> void)

## 4. 外部関数インターフェース (FFI) plugin

C言語などで書かれた共有ライブラリ (`.so` / `.dll`) の関数を呼び出す仕組み。これにより、Charlessでは不可能なOS機能（ソケット通信、GUIなど）を利用可能にします。

- **使用領域**: `050-059` (予約領域)
- **提案命令**:
    - `050`: **DL_LOAD** (ライブラリパス -> ハンドル)
    - `051`: **DL_CALL** (ハンドル, 関数名, 引数数, 引数... -> 戻り値)
        - スタックから引数を動的に取り出してC関数をコールする。

## 5. 並行処理 (Green Threads)

軽量スレッドによる並行処理をサポートします。

- **使用領域**: `760-769` (予約領域)
- **提案命令**:
    - `760`: **SPAWN** (関数アドレス -> スレッドID)
        - 指定したアドレスから新しいスレッドを開始。
    - `761`: **YIELD** (void -> void)
        - 現在のスレッドの実行権を譲る。
    - `762`: **JOIN** (スレッドID -> void)
        - 指定したスレッドの終了を待つ。

## 6. 名前空間 (Namespace) の概念導入

3桁命令の限界（1000個）を突破するための「モード切り替え」または「プレフィックス」アプローチ。

- **アイデア**: `999` を「拡張命令プレフィックス」とし、その次の3桁を別の命令セットとして解釈する。
    - 例: `999 001 200` -> 拡張セット1の命令001を実行。
    - これにより、実質無限に命令を拡張可能にする。

---

**優先度推奨**:
1. モジュールシステム (ファイル分割は必須)
2. 動的配列 (メモリ操作の簡易化)
3. FFI (機能拡張の近道)
